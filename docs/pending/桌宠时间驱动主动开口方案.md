# 桌宠时间驱动主动开口方案（待实现）

> 状态：方案 / 评审修订（2026-10-21 记录，未开工）
> 关联：`docs/pending/桌宠结合设计方案.md`（P0–P9 已完成）· TTS 见 `docs/pending/桌宠TTS语音方案.md`

## 0. 评审结论

时间驱动主动开口可以做，但第一版不应把每次触发都交给 AI。建议采用三层结构：

1. **触发层**只判断“今天是否有一个合适的时段事件”；
2. **内容层**默认从本地短句池取一句，AI 独白作为明确的可选档位；
3. **输出层**把气泡和 TTS 分开，是否出声交给统一的语音仲裁层（见 `桌宠TTS语音方案.md`）。

这样网关未启动、网络不可用或额度不足时，时间问候仍然可以正常工作；同时不会因为打开了 TTS 就让随机彩蛋和所有通知突然开始说话。

## 1. 现状：时间只触发动作，从不触发说话

这一点先说清楚，因为它决定了方案形态。当前所有与「时间」相关的逻辑都在 `src/pet/PetRoot.tsx` 的彩蛋定时器里（L831–892，间隔 = `pet_easter_egg_minutes` 分钟）：

| 触发源 | 现有行为 | 出处 |
|---|---|---|
| 节日（含农历/节气） | 只 `playTransient('festival', ...)` 播动作 | `getTodaysFestivalPlan` |
| 时段（早/午/晚） | 只播刷牙/早餐/午餐/晚餐动作 | `flavor.ts::timeSlot` + `pickSlotAction` |
| 空闲随机彩蛋 | 只播动作 + 一句固定台词 `lineForAction` | `pickFlavorAction` |

也就是说：**早上它只是默默刷牙，不会跟你说「早」。**

唯一的 AI 主动开口是 `usePetAutoSay`，但它只响应**业务事件**（签到成功/失败等，见 `AUTO_TRIGGER_TYPES`），且有 `AUTO_GAP_MS = 120_000` 节流 + `AUTO_PROBABILITY = 0.35`（35% 概率才说）。

## 2. 目标

让它在该说话的时候说话，而且**不变成骚扰**。

## 3. 方案

### 3.1 使用统一时钟检查，但不共享彩蛋节流

保留一个统一的时间检查入口，但时间主动开口不能直接复用 `pet_easter_egg_minutes` 的间隔。当前彩蛋间隔可调为 1～30 分钟；若两者共用，用户调慢彩蛋后，早 / 午 / 晚问候也会被延迟，甚至错过时段。

建议每 30～60 秒做一次轻量检查，彩蛋仍按 `pet_easter_egg_minutes` 单独节流。检查只产生一个候选事件，最终是否显示和是否朗读交给统一策略层；不要让多个定时器同时抢气泡或语音。

时间事件采用“进入时段后第一次有空时触发”的语义：忙碌时不追赶，时段结束后也不补播。每个事件使用 `${localDateKey(now)}#${eventType}` 去重。

### 3.2 触发源（按优先级）

| 触发 | 判定条件 | 台词示例 |
|---|---|---|
| 时段问候 | 当天首次进入早/午/晚时段 | 「早，今天想干点什么」 |
| 久坐提醒（后续） | 接入可靠系统活动信号后，连续活动 ≥90 分钟且无长休息 | 「两个小时了，站起来晃一下？」 |
| 深夜问候（后续） | 接入可靠系统活动信号后，23 点附近检测到近期活动 | 「差不多该收尾啦」 |

时段边界沿用 `flavor.ts::timeSlot`（早 5–10 / 午 11–13 / 晚 17–20，刻意错开留空以防整点连触两个时段），**不要另写一套**——两处边界不一致会出现「动作播了但话没说」或反之。

连续活动、久坐和“仍在使用”不能只看进程存活，桌宠窗口显示也不能证明用户在电脑前。Tauri 当前没有可直接复用的 Electron `powerMonitor`；如果没有 Rust 侧可靠的系统最后输入时间，就先不做久坐提醒和深夜催睡，宁可少一个功能，也不要误判后打扰。

第一版只实现**早 / 午 / 晚三个时段问候**。深夜事件保留为后续可选项，且默认不进入语音通道。

### 3.3 必须成组加上的约束

主动开口是所有桌宠功能里**最容易导致卸载**的一个。以下约束需要成组实现：

1. **统一自动发言上限**：默认 **4 次**。覆盖时间问候和事件自动点评，不覆盖用户主动对话；不能复用现有 `PET_SAY_DAILY_CAP = 200`，也不能只在前端内存里计数。
2. **静默时段**：复用 `flavor.ts::isQuietHour`（23–5 点）。第一版夜间完全静默，不设催睡例外；这与 TTS 方案保持一致。
3. **忙碌即静默**：将 `usePetAutoSay` 当前传入的 `isBusy` 判据提炼为共享策略，包括 `document.hidden`、对话输入中、对局中、拖拽中和全屏隐藏。时间问候、自动点评、语音统一使用同一判据。
4. **隐藏绝不说**：桌宠被隐藏（`pet_enabled=false`）或全屏被收起时不触发。看不见还在说话，既诡异又白花 token。
5. **每事件每天一次**：用 `${localDateKey(now)}#${eventType}` 做键去重。错过时段不补播。
6. **一键闭嘴**：右键菜单加「今天别主动说话」，当天压制时间问候、事件自动点评和对应 TTS；用户主动对话仍可使用，系统操作通知仍可显示。
7. **跨重启一致**：只持久化日期、自动发言计数和今日静音标记，不存对话内容。否则重启即可绕过上限或静音。

所有自动来源共用一个 `PetAutoPolicy`，至少维护 `lastAutomaticAt`、`dailyCount`、`silencedDate` 和事件去重集合。`usePetAutoSay` 与时间调度都调用它，不能各自维护一套间隔和上限。

### 3.4 Prompt 设计要点

只有用户选择 AI 独白档时才调用模型；本地档不需要网关，也不消耗额度。AI 提示不能写成报时器，系统提示要明确禁止报时：

```text
现在是周三上午 9:12，用户刚打开电脑。
用一句话自然地说点什么，像朋友随口一提。
不要说「现在是」「已经」「提醒您」，不要报出具体时间，
不要解释你为什么说话，不要用感叹号堆情绪。
```

否则模型极易输出「现在是上午九点十二分，建议您…」——那是闹钟，不是桌宠。

AI 档必须先确认网关在跑。网关不可用时回落到本地短句，不报错、不弹窗、不重试刷屏；本地档完全不检查网关。`usePetAutoSay` 现有的 `gatewayUpRef` 可以复用，但最终节流和每日预算由 `PetAutoPolicy` 统一决定。

### 3.5 设置项

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `pet_proactive_mode` | `Option<String>` | `None` → `off` | `off` / `local` / `ai`；分别表示关闭、仅本地短句、允许 AI 独白 |
| `pet_proactive_daily` | `Option<u32>` | `None` → 4 | 自动发言每日上限，夹到 0–12；用户主动对话不计入 |
| `pet_proactive_desk` | `Option<bool>` | `None` → 关 | 久坐提醒；第一版不实现，等可靠系统活动信号接入后再评估 |
| `pet_proactive_bedtime` | `Option<bool>` | `None` → 关 | 深夜问候；第一版不实现，默认永不在深夜发声 |

`pet_ai_mode` 继续控制现有的手动对话 / 业务事件自动点评；`pet_proactive_mode` 只控制时间事件，设置页必须分开说明。TTS 由 `桌宠TTS语音方案.md` 的独立设置控制，打开主动开口不会自动打开声音。

### 3.6 与现有动作、气泡和 TTS 的关系

- 时间事件先走现有 `timeSlot()` 和 `playTransient()`，动作与文字保持同一时段语义；
- 本地短句先显示气泡，再按语音设置提交给 TTS 仲裁层，调度器不直接调用 `speechSynthesis`；
- AI 独白由 `pet_say` 生成最终正文，成功后更新气泡并提交 TTS 仲裁；生成失败回落本地短句；
- 系统通知优先于普通主动内容，但第一版只显示通知，不朗读通知正文；
- 用户主动对话优先级高于时间问候和事件自动点评，低优先级内容不能截断用户回答。

## 4. 不做的

- 不做「报时」式播报（几点了几分了）
- 不做基于使用内容的推断（「我看你一直在写代码」这类）——越界，且容易说错
- 第一版不在深夜主动开口，后续也不默认开启催睡例外
- 不做跨天补播（错过了就算了，不补）
- 不把时间主动开口绑定到 `pet_easter_egg_minutes`
- 不在没有可靠系统活动信号时实现久坐提醒

## 5. 验收标准

1. `off` 状态下完全无主动发言；`local` 状态不依赖网关。
2. `ai` 状态网关不可用时回落本地短句，不报错、不弹窗。
3. 当天自动发言累计不超过上限，超了立即停；用户主动对话不受影响。
4. 23–5 点间不自动发声；第一版不实现深夜催睡。
5. 桌宠隐藏时不发言（观察日志无 `pet_say` 调用）。
6. 同一事件类型当天只出现一次，错过时段不补播（改系统时间跨天可复现）。
7. 点「今天别主动说话」后当天自动内容彻底安静，重启后仍保持；用户主动对话和系统通知不受影响。
8. 全屏应用 / 对话输入中 / 猜拳对局中不发言。
9. 调慢彩蛋间隔不会延迟时段问候；时间检查与彩蛋节流相互独立。

## 6. 成本

约 1.5～2 天（含统一策略、日期/计数持久化、时段问候、TTS 仲裁接线和回归测试）。久坐与深夜活动检测另行评估，不计入第一版。

## 7. 第一版决策

1. **默认模式**：`off`。用户需要主动选择本地短句或 AI 独白。
2. **默认每日上限**：4 次自动发言；范围 0～12。
3. **第一版触发**：只做早 / 午 / 晚时段问候；不做久坐提醒、不做深夜催睡。
4. **TTS 关系**：默认关闭，且自动内容默认只显示气泡；是否朗读由 TTS 方案中的独立范围设置决定。
