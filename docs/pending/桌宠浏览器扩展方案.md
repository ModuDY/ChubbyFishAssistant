# 桌宠浏览器扩展方案（待实现）

> 状态：方案 / 未开工（2026-10-19 记录）
> 关联：`docs/pending/桌宠结合设计方案.md`（P0–P3 已完成，P4 进行中）

## 1. 为什么做

上游 `PC2005-cloud/dsh-pet` 是**双端同源**：同一份宠物配置既能作为网页里的挂件，也能作为桌面悬浮窗，菜单里有 `web / desktop / both / none` 的「显示位置」开关。

我们目前只有桌面端（Tauri 透明窗口播 WebM）。做扩展的目的**不是**复刻那个开关，而是补一个桌面端天然拿不到的能力：

> **桌宠能感知浏览器里正在发生的事，并对此作出反应。**

典型场景：划词让它评一句、看视频太久被提醒、页面报错时安慰一句、配色跟着页面走。

## 2. 范围

**做**

- 浏览器扩展（Chrome / Edge，MV3）：在网页上渲染一只与桌面端**同一形象、同一人格**的桌宠
- 按需读取页面上下文（划词 / 标题 / 报错摘要），**默认不主动抓取整页**
- 与桌面端共用本地 API 网关：素材、人格、AI 对话都从网关取，不重复打包素材

**不做**

- 不做通用网页抓取（不读整页正文、不上传浏览记录）
- 不做多端状态实时同步（两端各播各的，配置以网关为准）
- 不做 Firefox / Safari（先只 Chrome/Edge，MV3）

## 3. 架构

```text
┌────────────────────────┐        HTTP (127.0.0.1)        ┌──────────────────────┐
│ 浏览器扩展 (MV3)        │ ────────────────────────────▶ │ 本地 API 网关         │
│  content script        │  GET  /pet/manifest           │ (api_server, 已有)    │
│  ├─ 渲染 <div> + WebM  │  GET  /pet/asset/:id          │  ├─ 素材（含 pet_pack）│
│  ├─ 划词/标题/报错采集  │  GET  /pet/status             │  ├─ 人格 / 状态        │
│  └─ 气泡               │  POST /pet/say  (流式)        │  └─ run_chat_completion│
└────────────────────────┘  POST /pet/event              └──────────────────────┘
                                       ▲
                                       │ 同一份
                                  ┌────┴─────┐
                                  │ 桌面端    │
                                  │ Tauri 窗口│
                                  └──────────┘
```

要点：**素材不打包进扩展**。扩展启动时向网关要 manifest，按需拉 `.webm`（可缓存到 `chrome.storage`）。这样换 `pet_pack`、改人格，两端天然一致。

## 4. 网关需要新增的接口

> 现有 `/pet/*` 都没有，需要新增；以下为契约草案。

| 方法与路径 | 说明 | 备注 |
|---|---|---|
| `GET /pet/manifest` | 返回 `{ pack, canvas, actions: [{ id, group, loop, url }] }` | `pack` 取自 `settings.pet_pack`，复用 `pet_pack_manifest` |
| `GET /pet/asset/:id` | 返回该动作的 WebM 流 | 需支持 `Range`（视频 seek）；路径按 id 查表，不接受任意文件名 |
| `GET /pet/status` | 返回 `{ display, persona, aiMode, bubble, opacity }` | `display` 见 §7 |
| `POST /pet/say` | `{ prompt, context?, stream: true }` → SSE（复用桌面端 `pet_say` 的流式实现） | 记账 `key_id = "internal:pet-web"`，与桌面端分开审计 |
| `POST /pet/event` | 扩展上报轻量事件 `{ type, url?, title?, ms? }` | 仅用于本地节流/触发策略，不落盘原文 |

**CORS**：只允许扩展 origin（`chrome-extension://<id>`）与 `http://127.0.0.1`；不用 `*`。

**鉴权**：扩展首次连接时用户在主窗口点「授权浏览器扩展」，生成一次性 `pet-web` token 存到 `chrome.storage.local`；后续请求带 `Authorization: Bearer <token>`。网关校验该 token 独立于 API Key。

## 5. 权限与隐私（红线）

1. **最小站点授权**：`host_permissions` 默认只放用户勾选的站点，**不用 `<all_urls>`**；`activeTab` 作为默认交互路径（用户点击扩展图标/右键菜单时才临时获得当前页权限）。
2. **显式触发优先**：只在「划词右键 / 点扩展图标 / 用户勾选的功能」时读取，不做后台静默抓取。
3. **最小上下文**：默认只发「选中文本（≤500 字）」或「页面标题 + 域名」；**永不**发整页 `innerText`。
4. **可见提示**：读取时气泡先显示「我看了这段」，再给评论；用户能感知。
5. **本地闭环**：内容只发到本机网关（127.0.0.1），不经任何第三方中转；日志不记录正文。
6. **可一键关闭**：扩展 popup 里一个总开关，关掉后不再注入任何 script。

## 6. 功能分期

### P0 · 划词点评（最小可用，约 2 天）

- 右键菜单「让大肥鱼看看」→ 取当前选区 → `POST /pet/say` → 气泡流式输出
- 气泡样式复用桌面端（透明度/圆角/打字机），但**用 Shadow DOM 隔离**，避免被宿主页面 CSS 污染
- 只注入动作「点击回应 / 思考」两三个，不加载全部 31 个素材

### P1 · 感知类玩法（每项 0.5 天）

| 功能 | 读取内容 | 触发 |
|---|---|---|
| 摸鱼提醒 | 当前 tab `title` + 停留时长 | 同一域名 >30min，且用户已授权该站点 |
| 报错安慰 | `window.onerror` 摘要（≤200 字） | 同一页面 5 分钟内首次报错 |
| 主题联动 | 页面主色（取 `body` 背景色/主按钮色） | 切页时，仅本地计算，不上传 |

### P2 · 显示位置（约 1 天，最后做）

- `settings.pet_display: 'web' | 'desktop' | 'both' | 'none'`
- 桌面端：读到 `web`/`none` 就 `hide()`；扩展：读到 `desktop`/`none` 就不渲染
- 菜单/托盘同步展示（与现有 `pet_enabled` 的同步机制一致，见 AGENT §5.5）
- 「都不」是单向门：只能从设置页恢复（对齐上游交互）

## 7. 技术要点

**MV3 骨架**

```text
extension/
├─ manifest.json        // mv3, permissions: ["storage","contextMenus","activeTab"]
├─ content.js           // 注入桌宠容器（Shadow DOM）
├─ pet.js               // 渲染/气泡/素材拉取
├─ background.js        // 右键菜单、token 管理、请求网关
└─ popup.html           // 总开关 + 站点授权 + 授权 token
```

**样式隔离**：容器用 `attachShadow({ mode: 'closed' })`，所有样式写在 shadow 内的 `<style>`；宿主 `z-index` 冲突用 `all: initial` + 极高 `z-index`（如 `2147483646`）兜底。

**指针**：默认 `pointer-events: none`，只有角色包围盒与气泡可交互（复用桌面端 `hitBox` 思路：采样首帧 alpha 得到包围盒）。

**视频**：`<video muted playsinline>` + WebM(VP9+alpha)。Chrome 支持，但**需验证**：alpha 在普通网页里（非 Electron）是否完整保留——这是 P0 的第一个技术验证点，若不行则退回 PNG 序列 + Canvas（桌面端已放弃该方案，因为 alpha 在 WebView2 里没问题，但浏览器需实测）。

**网关 CORS 与 Range**：`/pet/asset` 必须支持 `Range`，否则视频不能 seek，循环播放会重头拉流。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 浏览器里 VP9 alpha 不生效 | 宠物背景变黑块 | P0 第一件事做验证；不行就换 PNG 序列（体积换兼容） |
| 注入样式污染宿主页面 | 网站排版错乱 | Shadow DOM + `all: initial`；默认只用 `activeTab` 注入 |
| 任意网页可调本地网关 | 隐私/滥用 | origin 白名单 + pet-web token；网关默认拒绝未知 origin |
| 素材走 HTTP 拉取变慢 | 首次出场延迟 | 缓存到 `chrome.storage`（IndexedDB 存 Blob），只拉用到的动作 |
| 扩展商店审核 | 无法上架 | 自用先「加载已解压的扩展程序」，不依赖商店 |

## 10. 验收标准（P0）

1. 在任意网站选中一段中文 → 右键「让大肥鱼看看」→ 3 秒内气泡开始流式输出
2. 宠物背景完全透明（无黑底/白底），角色边缘无明显锯齿
3. 宿主页面样式不被污染（在 GitHub、知乎、B 站各验一遍）
4. 关闭扩展总开关后，页面无任何注入残留
5. 网关日志里只出现 token 与字数，不出现正文
