## 备份与调度

应用启动 90 秒后开始检查，此后每 60 秒检查一次，独立于签到调度线程。每日任务在当天到达指定时间后执行一次，错过时间后重新打开程序会在当天补跑。每 6 / 12 小时模式按 Unix 时间分段，每段最多创建一次计划备份；不会补发停机期间的全部历史时段。退出程序后不执行邮件任务。

备份不会扫描机器上的其他程序、浏览器或任意文件，也不刷新令牌。范围仅限本应用 SQLite 账号表和对应保险库记录，包括 JWT、刷新令牌、WB access token、Qoder PAT / machine token、豆包会话 Cookie，以及恢复所需的账号元数据和设备标识。不包含 SMTP 授权码、API 网关密钥、客户端登录快照、会话、分组和标签。

所有源数据读取成功后才生成附件。数据库损坏行、保险库打开/解密/格式错误会中止整次备份；元数据账号本就没有凭据时仍可备份，并在历史与恢复预览中提示。没有账号时不创建空附件。内存降级或数据库恢复模式暂停备份与恢复，修复并重启后再操作。

本地只写密文到 `%APPDATA%\AIWorkAssistant\backups\accounts\aiwork-<UUID>.aiwbak`，先写临时密文并同步，再重命名。邮件发送前重新验证附件认证标签；文件损坏或丢失会取消发送。历史最多保存 50 条元数据，面板展示最近 10 条。也可在未配置邮箱时手动生成本地备份，或用“导出加密附件”保存到新文件。

SMTP 仅支持 465 TLS 或 587 强制 STARTTLS，网络操作超时 30 秒。明确的 SMTP 4xx 拒绝按 5、15、60 分钟重试同一份附件，最多额外 3 次；验证失败暂停自动任务，重新保存配置后恢复。连接失败、超时或发送确认中断归为“状态未知”，不自动重发；先检查邮箱再手动重试。应用在发送中退出时，历史保留发送中断提示，不自动重发原附件。设置变更取消旧的重试计划。

## 在另一台机器恢复

1. 安装应用，点击左上角品牌并验证入口密码。
2. 点击“选择附件并预览恢复”。恢复密码留空时使用指定默认密码，也可以明确填写附件密码。
3. 面板展示平台、名称、到期时间、凭据/刷新令牌是否存在，以及新增或跳过的结果；不会把完整凭据传给前端。
4. 确认补入新账号。预览 5 分钟内有效，仅驻留内存，关闭或重新解锁会失效。

恢复仅新增账号，按平台内部账号 ID 及非空稳定 UID 去重；不覆盖已存在账号的较新凭据、元数据和 Qoder 指纹，不自动切换客户端。新 Qoder 账号沿用附件中的设备指纹，Trae 沿用设备映射。分组字段在新机器清空，之后可重新分组。过期令牌是否能继续使用取决于上游服务及刷新令牌状态。仅 Cookie 的豆包账号恢复后不具备客户端快照。

凭据先写入目标机器自己的保险库，SQLite 在单个事务中新增账号占位行。数据库写入失败则回滚事务并补偿恢复原保险库内容；补偿失败会明确报错，请保留原附件。异常退出最多留下加密孤儿凭据，账号行不会先于保险库发布。

## 格式与开发契约

- 文件头：`AIWBK001`（8 字节）+ 随机 salt（16）+ nonce（12）+ AES-256-GCM 密文/认证标签（16 字节 tag）。格式标记作为 AAD 验证。
- Argon2id v19 固定参数：19,456 KiB、2 轮、1 并行度、32 字节密钥。salt / nonce 取 OS CSPRNG，失败直接中止。与现有 Qoder 导出格式独立，不影响其兼容解密。
- 密文上限 15 MiB，JSON 格式 `kind=aiwork-account-backup,version=1`。解密后校验平台白名单、账号标识、元数据 DTO、重复账号及字段类型。恢复只操作固定的账号、令牌和设备映射表。
- 非敏感配置与历史在 SQLite KV：`account_backup_config`、`account_backup_history`、`account_backup_runtime`；独立计划游标 `account_backup_last_schedule` 避免历史裁剪后当天重复创建；SMTP 授权码在保险库 `ns:backup:mail`。
- `backup_unlock(password)` 返回随机会话；`backup_action(session, request)` 接受 `action` 为 status、save、test_mail、run、retry、export、preview、restore、lock 的对象。所有命令在 Rust 校验会话，耗时操作使用 blocking worker；后台线程内部直接调度，操作锁防止手动/自动任务重叠。
- SQLite 快照读取事务结束后再打开保险库。备份与恢复按 JWT / 平台池 / token store / 设备锁顺序保护关键数据；恢复保险库持锁期间提交 SQLite，避免发布占位凭据。
- 回归使用临时目录、合成凭据和模拟 SMTP，不读取真实账号、不发送真实邮件。覆盖认证加密、错误密码与篡改、严格读取、会话到期、计划与有限重试、损坏附件禁止发送、跨目录新增恢复、UID 去重、设备指纹与保险库补偿。
